## CORRECTION — CI-log evidence (2026-08-13) — 12003 is NOT a dup of 11548

Pulled the real CI job log (run #30850615308, job `91817509456`, station `pldm-edk0-z3a`) and compared to a
sibling station in the **same run / manifest / FC image**. The earlier "duplicate of 11548" call was
**wrong**.

**Confirmed (from the log):**
- **12003 / `edk0-z3a` — device ABSENT from the PCI bus.** Only detection point in the whole job:
  `Detected Simulator device` → `hostname indicates a Palladium platform but no PCI device with vendor 208b
  was found - refusing to run simulator`. No `Detected Palladium device`, no `atl device found [208b:0001]`
  anywhere in the job. Failing suite = `spark_basic_test` pre-task; fails at the device-presence gate,
  before any test. (The other `208b` strings in the log are an SSH temp-key UUID `208b45a5…`, unrelated.)
- **Same run, same FC image, sibling `edk0-z2a` — device PRESENT:** `Detected Palladium device (revision:
  0x23)` + `atl 0000:af:00.0: atl device found [208b:0001] (rev 23)`.
- **11548 — device PRESENT then FW-boot timeout:** `atl device found [208b:0001] (rev 55)` →
  `probe with driver atl failed with error -110`.

**Conclusion:** the identical FC image enumerates `208b` fine on a sibling station in the same run ⇒ this is
**not** a systemic image/FW enumeration bug. 12003's device-absence on `edk0-z3a` is a **per-station
Palladium emulation bring-up** condition (design/image not loaded on that box, host PCIe transactor-link
down, or the design crashed and dropped the link) — owned by station/emulation infra + `ip-pcie-kmd`/
emulation-utils, **not** the `ip-pcie-firmware-ep` FW-boot path that 11548 tracks. **11548 = device present,
FW didn't boot. 12003 = device never appeared.** Different stage, different owner.

**Unverified:** the exact sub-cause of the absence (failed `pd_load` vs host-link down vs design crash) — the
GitHub runner log proves absence but the EDK/station-side load log isn't in this artifact. Next step to pin
it: the `pldm` skill on `pldm-edk0-z3a` / `mgmt-edk0-z3a` — check the design-load (`pd_load`) status and
host `lspci` at the time of the run.

**Revised recommendation:** do **not** link 12003 as a duplicate of 11548. Reclassify as an
emulation/station bring-up failure on `edk0-z3a` (label `palladium_bugs` / infra). Answer Oded accordingly:
the `208b`-not-appearing failure is a station-side emulation bring-up miss (device never presented to the
host), distinct from the 11548 FW-boot regression; the same image enumerated fine on sibling stations that
run.
